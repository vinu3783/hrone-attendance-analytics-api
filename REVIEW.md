# REVIEW.md

Review of the starter `app/main.py`. Line numbers refer to the **original starter file**. Each row was reproduced against
the unmodified starter running on MongoDB 7.0 with the sample data, except rows marked *(from code)*, which follow directly from reading the code and were not run against the starter.
Every fix is covered by a test in `tests/`.

| 1 | module, L22 | `MongoClient(...)` is created without `tz_aware=True`, so every BSON date comes back **naive**. Any later `.timestamp()` or comparison with an aware datetime treats it as server-local time, or raises `TypeError` when an aware value meets a naive one. | `GET /attendance` returned `"punch_in": "2026-07-14T04:02:00"`: a naive ISO string with no zone. | Client created with `tz_aware=True, tzinfo=UTC`; all instants are aware UTC internally. |

## Examined and judged not to be defects

- `load_dotenv()` (L20): its default `override=False` means real environment variables win over `.env`, as the contract requires. Kept.
- `IST = timezone(timedelta(hours=5, minutes=30))`: correct; India has no DST, so a fixed offset is right.
- String comparison of `"YYYY-MM-DD"` dates in `list_attendance` (`$gte` / `$lte` on strings): correct, because zero-padded ISO dates sort lexicographically in chronological order. The rewrite keeps dates as strings, per DATA_MODEL.md.
- `late_minutes` counted **from `shift_start`**, not from the end of the grace period (L36): this matches R2. Only the threshold comparison (#5) and the time zone (#4) were wrong.
- `doc.pop("_id", None)` after `insert_one` in `create_employee`: needed, because `insert_one` adds `_id` to the dict. The rewrite builds responses explicitly instead.
- Defaults `shift_start="09:30"`, `shift_end="18:30"`, `status="PRESENT"`: match the contract.
- Using `int(... / 60)` as the floor in `compute_overtime`: equivalent to floor for the non-negative values that matter. The real bugs there are #8 and #9.
- `if body.punched_at` (L102) treats `0` as "not given". This would be a bug, but `0` is now rejected by validation before it reaches this point, so it cannot occur.
